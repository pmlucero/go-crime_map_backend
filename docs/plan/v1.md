# v1 implementation plan

- Status: Approved
- Last updated: 2026-10-23
- Spec: [core.md](../spec/core.md) v0.1 (updated whenever the spec version changes)

This plan orders the work needed to meet every acceptance criterion of the [core spec](../spec/core.md). It says *in what order* things are done and *how* progress is tracked. *What* is built is defined by the spec and the [ADRs](../adr/README.md). If they disagree, the spec wins, and this plan is updated.

## Starting point

The API works end to end: create, list, detail, status change, soft delete, statistics and API key authentication. The spec was written after the code, so the gap is in error handling and input validation, not in missing features. 16 of 26 acceptance criteria are met.

## Milestones

| # | Milestone | Scope | Acceptance criteria |
|---|---|---|---|
| M0 | Workflow and CI | Contributing guide, `CLAUDE.md`, PR and issue templates, Dependabot, golangci-lint, required checks, protected `main` | — |
| M1 | English codebase and traceability | Translate comments, error messages and test names to English. Tests reference the criteria they verify. | All criteria marked Met |
| M2 | Error contract | Typed errors compared with `errors.Is`, mapped to `400`, `404` and `500` in one place. `500` responses hide internal details. | AC-08, AC-09, AC-11, AC-18, AC-19, AC-22, AC-25 |
| M3 | Input and listing | Accept zero coordinates. Return an empty `items` array. Apply the list filters. | AC-07, AC-15, AC-16 |
| M4 | Cleanup | Remove the unused use case implementation (`internal/infrastructure/usecases`), the unwired handlers (`internal/api`, `internal/security` HTTP code) and the duplicate repository in `internal/infrastructure/database`. | — |
| M5 | Authentication integration tests | Test the middleware against PostgreSQL, not only with mocks ([ADR 0005](../adr/0005-api-key-authentication.md)). | AC-01, AC-02, AC-03 |

A milestone is done when its criteria are marked Met in the spec, in the same PR that meets them, and CI is green.

## Working rules

- One milestone can span several PRs. Each PR stays focused.
- Criteria are marked Met only when a test referencing them passes in CI.
- New behavior that is not in the spec needs a spec change first (see `CONTRIBUTING.md`).

## Later

Not scheduled. Each item needs a spec change, and some need an ADR:

- Search by radius around a point.
- API key management through the API, with hashed keys (superseding ADR 0005).
- A single migration tool instead of `schema.sql` plus `migrations/`.
- Structured logging with `log/slog`, and configuration fully from environment variables.
- Rate limiting.
